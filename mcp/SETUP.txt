putty-mcp - the MCP bridge that ships inside PuTTY.app
=====================================================

PuTTY is a session; this folder is the other end of it. An MCP client (OpenCode,
Claude Desktop, ...) runs the program below, which speaks MCP on stdio and talks
to a *running* PuTTY window over a Unix socket - so the agent works in the window
you are looking at, and you can watch it, take over, and answer what it cannot.

    the program:  bin/putty-mcp.mjs          (run it with node)


1. What you need
-------------------------------------------------------------------------------
Node.js 20 or newer, which also brings npm:

    node --version        # want v20 or newer
    command -v node       # note the full path for step 3

The bridge's two npm packages are not in this folder - installing them in place
would change PuTTY.app and break its code signature. Install them globally, once:

    npm install -g '@modelcontextprotocol/sdk@^1.32.2' 'zod@^3.25.76'

Node will not look in the global place by itself: it searches for `node_modules`
in every directory *above* the file it runs, and this folder is under
/Applications. So point that search at the global one:

    ln -s "$(npm root -g)" /Applications/node_modules

(Skip that if /Applications/node_modules already exists.) It is one symlink
outside every app - nothing is written inside PuTTY.app - and it is what makes
the path in step 3 work. Reinstalling or updating PuTTY.app does not undo it, so
the bridge always runs the app's own copy, at whatever version you installed.

Prefer the exact versions this bridge was tested with? Then copy the folder out
and install there instead, which uses the shipped package-lock.json:

    cp -R "/Applications/PuTTY.app/Contents/Resources/putty-mcp" ~/putty-mcp
    cd ~/putty-mcp && npm install

and point step 3 at ~/putty-mcp/bin/putty-mcp.mjs. (If you have the putty-beter
source, `cd mcp && npm install` there does the same.)

Copy from the Resources path - it holds the real files. The
.../Contents/MacOS/putty-mcp of the same name is the same folder through a
symlink, so either path works in step 3.


2. Offer a session to it (in PuTTY)
-------------------------------------------------------------------------------
The socket only exists while at least one session is offered:

  a. Load the session in PuTTY.
  b. Session -> Automation (MCP) -> "Offer this session to an MCP client".
     "Also allow an MCP client to type into this session" lets the agent drive
     it as well; leave it off for read-only.
  c. Save, then reopen the session - the settings are read when the window opens.


3. Point the client at it
-------------------------------------------------------------------------------
For OpenCode, add this to ~/.config/opencode/opencode.json, inside the "mcp"
object, with your own two paths (the node from step 1, and the copy):

    {
      "mcp": {
        "putty-mcp": {
          "type": "local",
          "command": [
            "/opt/homebrew/bin/node",
            "/Users/YOU/putty-mcp/bin/putty-mcp.mjs",
            "mcp"
          ]
        }
      }
    }

Then restart OpenCode. Any other MCP client works the same way: it runs
`<node> <...>/bin/putty-mcp.mjs mcp` and speaks MCP on stdio.


4. Checking it without an agent
-------------------------------------------------------------------------------
The same program is a plain command-line client - the first thing to reach for
when something is wrong:

    node ~/putty-mcp/bin/putty-mcp.mjs list       # sessions PuTTY is offering
    node ~/putty-mcp/bin/putty-mcp.mjs read 1     # a session's output
    node ~/putty-mcp/bin/putty-mcp.mjs screen 1   # the visible screen
    node ~/putty-mcp/bin/putty-mcp.mjs help

`list` printing nothing means no session is offered (step 2), or PuTTY is not
running.
